# Interaction Patterns — Design Knowledge

> Motion and interaction recipes for pages generated by Proof.
> All patterns are progressive enhancements — pages must work fully without animations.
> Source: validated in Product Page (Meridian/Vaultline), distilled from 10 external library studies (Motion.dev, Paper Shaders, Canvas UI, Great UI, ThreeUI, interior.dev, Skiper UI).

**Rule: motion must show the product doing something. Fade-up reveals are a fallback, used on at most half the sections.** Use §1.5 (product-serving motion) first. Use §2–§3 only where a section has no product visual to bring to life. If every section fades up the same way, the page reads as AI-generated.

---

## 1. Motion Tokens

These are the source of truth for all animation timing. Quote verbatim — do not invent values.

```
Entrance duration:     0.8s
Entrance easing:       cubic-bezier(0.16, 1, 0.3, 1)     /* decelerate — fast start, gentle stop */
Entrance distance:     32px (section), 24px (card), 16px (small element)

Stagger interval:      100ms (cards), 80ms (logos/small items), 150ms (large blocks)

Hover duration:        0.2s ease-in-out                    /* all hover transforms; the active style file's §6 timing wins when it differs */
Button hover lift:     translateY(-1px)                    /* from visual-style.md */
Card hover lift:       translateY(-4px)                    /* cards, distinct from buttons */

Counter duration:      2000ms                               /* exception: applies to counting animation only,
                                                               not to entrance or hover — those stay ≤ 1s */
Counter easing:        ease-out cubic: 1 - (1-t)^3

Marquee speed:         30s per full cycle                   /* exception: continuous loop, ceiling does not apply */

Max duration ceiling:  1s (entrance animations and stagger sequences only;
                          counter and marquee are exempt — see above)
```

### Reduced-Motion Contract (mandatory)

All animations are progressive enhancements. When `prefers-reduced-motion: reduce` is active, content must appear instantly with no transform or delay.

- **CSS**: Every animation rule goes inside `@media (prefers-reduced-motion: no-preference) { ... }`
- **JS**: The first line of any animation script must be: `if (window.matchMedia('(prefers-reduced-motion: reduce)').matches) return;`
- **Fallback**: Elements start at `opacity: 1; transform: none` — the animated state is the default, and the `@media` block overrides it to the "before" state

## 1.5 Product-Serving Motion

These recipes make a synthetic product visual (`data-mock`, see `shared/product-visuals.md`) do what the product does: new rows arrive, a cursor clicks, a reply is typed, an alert appears, a number moves, a chart draws. Read this section before §2–§3.

**Evidence**: the Mobbin previews are still images, so motion shows up only as cues frozen in the frame: a cursor in 11/55 product visuals, a typing caret in 2, a toast in 2, and a mid-process state in 3 (rows still "Calculating…", "Step 6 Complete", chart bars caught mid-draw). (Craft research, pattern 6.)

**Rules**:

- **One recipe per visual.** Never stack a cursor, a caret, and a toast in the same mock (the evidence shows one cue at a time).
- **The static HTML is the final state.** Rows, the focused element, the typed text, the toast, the final number, and the drawn line are all in the markup. JS sets the "before" state only when motion is allowed (Reduced-Motion Contract).
- **Play once.** No loops. No style defines a loop interval.
- **Timing comes from §1.** Each movement uses the entrance duration and easing (0.8s, `cubic-bezier(0.16, 1, 0.3, 1)`) or the hover duration. Typing and number ticks use the counter duration (2000ms), the same exemption from the 1s ceiling that counters have: content changes inside the mock, nothing on the page is held back.
- **A section whose mock has a recipe skips Scroll Reveal (§2).** Its motion replaces the fade-up.

**Shared trigger** — include once, before the recipes, **copied verbatim** (do not rewrite it). The hero mock starts on load, other mocks when any part of them scrolls into view; a tall mock with a 10% threshold never fires above the fold, and the hero then shows an empty product. The delays are the ones from §5.

```js
function onMockVisible(mock, run) {
    if (window.matchMedia('(prefers-reduced-motion: reduce)').matches) return;
    if (mock.closest('[data-section="hero"]')) { setTimeout(run, 300); return; }  // §5 hero trigger
    var io = new IntersectionObserver(function(entries) {
        if (!entries[0].isIntersecting) return;
        io.disconnect();
        setTimeout(run, 400);                                                     // §5: 400ms after it appears
    }, { threshold: 0 });
    io.observe(mock);
}
```

### A. Rows stream in

**When**: a feed, log, inbox, incident list, or order table: anything that receives new records. Mark the 2–3 newest rows with `data-stream`. Three rows fit the 1s ceiling: (3 − 1) × 80ms + 0.8s = 0.96s.

```css
@media (prefers-reduced-motion: no-preference) {
    [data-mock] [data-stream] {
        transition: opacity 0.8s cubic-bezier(0.16, 1, 0.3, 1),
                    transform 0.8s cubic-bezier(0.16, 1, 0.3, 1);
    }
    [data-mock] [data-stream].is-before { opacity: 0; transform: translateY(-16px); }  /* small-element distance */
}
```

```js
(function() {
    if (window.matchMedia('(prefers-reduced-motion: reduce)').matches) return;
    document.querySelectorAll('[data-mock]').forEach(function(mock) {
        var rows = mock.querySelectorAll('[data-stream]');
        if (!rows.length) return;
        rows.forEach(function(row, i) {
            row.classList.add('is-before');
            row.style.transitionDelay = (i * 80) + 'ms';    // stagger: small items
        });
        onMockVisible(mock, function() {
            rows.forEach(function(row) { row.classList.remove('is-before'); });
        });
    });
})();
```

### B. Cursor moves to one element and clicks it

**When**: the visual has one primary action or one tab whose click is the point: "Save issue", "Deploy", "+ New note", a report tab. Evidence: a cursor on the primary button (30), on a tab (41), clicking a play button (5). For collaboration products, add a name tag ("Maya") inside the cursor span (43, 45, 54).

In the HTML, give the target `class="pv-target is-focused"` and an `id`, and place the cursor over it with `left`/`top` percentages. JS moves the cursor in from the mock's lower-right corner and applies the focused state when it arrives.

```html
<span class="pv-cursor" data-cursor-for="pv-deploy" style="left: 78%; top: 86%" aria-hidden="true">
  <svg viewBox="0 0 14 20"><path d="M1 1v16l4.5-4 3 6.5 2.5-1-3-6.5H14z"/></svg>
</span>
```

```css
.pv-cursor     { position: absolute; width: 16px; pointer-events: none; }
.pv-cursor svg { display: block; fill: var(--text); stroke: var(--bg); }
@media (prefers-reduced-motion: no-preference) {
    .pv-cursor { transition: transform 0.8s cubic-bezier(0.16, 1, 0.3, 1); }
    .pv-target { transition: background-color 0.3s linear, color 0.3s linear; }  /* style §6 color timing */
}
```

```js
(function() {
    if (window.matchMedia('(prefers-reduced-motion: reduce)').matches) return;
    document.querySelectorAll('[data-mock] .pv-cursor[data-cursor-for]').forEach(function(cur) {
        var mock = cur.closest('[data-mock]');
        var target = document.getElementById(cur.getAttribute('data-cursor-for'));
        var m = mock.getBoundingClientRect(), c = cur.getBoundingClientRect();
        cur.style.transition = 'none';
        cur.style.transform = 'translate(' + (m.right - c.right) + 'px,' + (m.bottom - c.bottom) + 'px)';
        target.classList.remove('is-focused');
        onMockVisible(mock, function() {
            cur.style.transition = '';
            cur.style.transform = 'none';
            cur.addEventListener('transitionend', function() {
                target.classList.add('is-focused');
            }, { once: true });
        });
    });
})();
```

### C. Typing caret writes one line

**When**: an AI prompt, a chat reply, a search box, or a command palette (35, 47, 54). Put the final text in a `data-type` element followed by the `.pv-caret` from `shared/product-visuals.md` Recipe 7. Keep the line under about 60 characters so it reads at a typing pace inside 2000ms.

```js
(function() {
    if (window.matchMedia('(prefers-reduced-motion: reduce)').matches) return;
    document.querySelectorAll('[data-mock] [data-type]').forEach(function(el) {
        var full = el.textContent;
        el.textContent = '';
        onMockVisible(el.closest('[data-mock]'), function() {
            var start = performance.now();
            function frame(now) {
                var t = Math.min((now - start) / 2000, 1);           // counter duration (§1), constant rate
                el.textContent = full.slice(0, Math.round(full.length * t));
                if (t < 1) requestAnimationFrame(frame);
            }
            requestAnimationFrame(frame);
        });
    });
})();
```

The caret stays solid. No style defines a blink interval, so do not add one.

### D. Toast slides in

**When**: the product's value is an alert or a notification: a page from an on-call tool, a priority lead, a payment received (4, 20). Use `.pv-toast` from `shared/product-visuals.md` (Recipe 8, or a floating card in Recipe 2). The toast names the same ID or person as the main UI (4).

```css
@media (prefers-reduced-motion: no-preference) {
    [data-mock] .pv-toast {
        transition: opacity 0.8s cubic-bezier(0.16, 1, 0.3, 1),
                    transform 0.8s cubic-bezier(0.16, 1, 0.3, 1);
    }
    [data-mock] .pv-toast.is-before { opacity: 0; transform: translateY(16px); }  /* small-element distance */
}
```

```js
(function() {
    if (window.matchMedia('(prefers-reduced-motion: reduce)').matches) return;
    document.querySelectorAll('[data-mock] .pv-toast').forEach(function(toast) {
        toast.classList.add('is-before');
        onMockVisible(toast.closest('[data-mock]'), function() { toast.classList.remove('is-before'); });
    });

```

### E. A number ticks inside the mock

**When**: one live metric in a dashboard mock: users online, today's spend, open incidents (7: "Users online 298"; validated as animated hero dashboard counters on the Product page). The number moves from a nearby value to its final value. It does not count up from zero, which would read as a stats counter rather than live data. It uses `data-tick-*`, not §5's `data-count-*`, so the §14 script does not also animate it. Do not tick a value whose cents sit in a separate `.pv-cents` span.

```html
<span data-tick-from="48219.40" data-tick-to="48382.09" data-tick-decimals="2" data-tick-prefix="$">$48,382.09</span>
```

```js
(function() {
    if (window.matchMedia('(prefers-reduced-motion: reduce)').matches) return;
    document.querySelectorAll('[data-mock] [data-tick-to]').forEach(function(el) {
        var from = parseFloat(el.getAttribute('data-tick-from'));
        var to = parseFloat(el.getAttribute('data-tick-to'));
        var dec = parseInt(el.getAttribute('data-tick-decimals'), 10) || 0;
        var pre = el.getAttribute('data-tick-prefix') || '', suf = el.getAttribute('data-tick-suffix') || '';
        function show(v) {
            el.textContent = pre + v.toLocaleString('en-US', { minimumFractionDigits: dec, maximumFractionDigits: dec }) + suf;
        }
        show(from);
        onMockVisible(el.closest('[data-mock]'), function() {
            var start = performance.now();
            function frame(now) {
                var t = Math.min((now - start) / 2000, 1);          // counter duration (§1)
                show(from + (to - from) * (1 - Math.pow(1 - t, 3))); // counter easing (§1)
                if (t < 1) requestAnimationFrame(frame);
            }
            requestAnimationFrame(frame);
        });
    });
})();
```

### F. A chart line draws

**When**: a chart card is the focal element: spend over a month, latency, revenue (40, 41, 42). Use `pathLength="1"` so no length measuring is needed. An optional endpoint dot marks "today" (40) and appears when the line finishes. A dashed comparison line (40) stays static. Do not give it `pathLength="1"`, because its dash pattern would scale with it.

```html
<svg class="pv-chart" viewBox="0 0 300 100" preserveAspectRatio="none">
  <path class="pv-line" data-draw pathLength="1" d="M0 82 L43 74 L86 77 L129 58 L172 61 L215 39 L258 44 L300 21"/>
  <circle class="pv-end" cx="300" cy="21" r="3"/>
</svg>
```

```css
.pv-line { fill: none; stroke: var(--text); stroke-width: 1px; vector-effect: non-scaling-stroke;
           stroke-dasharray: 1; stroke-dashoffset: 0; }
.pv-end  { fill: var(--text); }
@media (prefers-reduced-motion: no-preference) {
    .pv-line { transition: stroke-dashoffset 0.8s cubic-bezier(0.16, 1, 0.3, 1); }
    .pv-line.is-before { stroke-dashoffset: 1; }
    .pv-end  { transition: opacity 0.3s linear; }          /* style §6 color/opacity timing */
    .pv-end.is-before { opacity: 0; }
}
```

```js
(function() {
    if (window.matchMedia('(prefers-reduced-motion: reduce)').matches) return;
    document.querySelectorAll('[data-mock] .pv-line[data-draw]').forEach(function(line) {
        var dot = line.ownerSVGElement.querySelector('.pv-end');
        line.classList.add('is-before');
        if (dot) dot.classList.add('is-before');
        onMockVisible(line.closest('[data-mock]'), function() {
            line.classList.remove('is-before');
            line.addEventListener('transitionend', function() {
                if (dot) dot.classList.remove('is-before');
            }, { once: true });
        });
    });
})();
```

## 2. Scroll Reveal

The foundation pattern. Sections fade in and slide up when they enter the viewport.

**When to use**: Fallback for content sections with no product-serving motion (§1.5): Features, Social Proof, CTA, FAQ, How It Works, Stats, Integrations, Use Cases. At most half of the page's content sections get it (top rule). Leave the others static. NOT on Nav or Footer.

### CSS

```css
@media (prefers-reduced-motion: no-preference) {
    .reveal {
        opacity: 0;
        transform: translateY(32px);
        transition: opacity 0.8s cubic-bezier(0.16, 1, 0.3, 1),
                    transform 0.8s cubic-bezier(0.16, 1, 0.3, 1);
    }
    .reveal.visible {
        opacity: 1;
        transform: translateY(0);
    }
}
```

### JS

```js
(function() {
    if (window.matchMedia('(prefers-reduced-motion: reduce)').matches) return;

    var observer = new IntersectionObserver(function(entries) {
        entries.forEach(function(entry) {
            if (!entry.isIntersecting) return;
            entry.target.classList.add('visible');
            observer.unobserve(entry.target);
        });
    }, { threshold: 0.1 });

    var sections = document.querySelectorAll('section.reveal');
    for (var i = 0; i < sections.length; i++) observer.observe(sections[i]);
})();
```

### HTML

Add `class="reveal"` to each `<section>` that should animate in. Do NOT add it to `<nav>` or `<footer>`.

## 3. Child Stagger

Grid children (cards, logos, steps) enter one by one with incremental delay after their parent section reveals.

**When to use**: Feature grids, integration grids, logo walls, how-it-works steps, use-case grids.

### CSS

```css
@media (prefers-reduced-motion: no-preference) {
    /* Cards start below and fade in with parent */
    .reveal [data-stagger-child] {
        opacity: 0;
        transform: translateY(24px);
        transition: opacity 0.6s cubic-bezier(0.16, 1, 0.3, 1),
                    transform 0.6s cubic-bezier(0.16, 1, 0.3, 1);
    }
    .reveal.visible [data-stagger-child] {
        opacity: 1;
        transform: translateY(0);
    }

    /* Small items (logos) use shorter distance */
    .reveal [data-stagger-child="small"] {
        transform: translateY(16px);
        transition-duration: 0.5s;
    }
    .reveal.visible [data-stagger-child="small"] {
        transform: translateY(0);
    }
}
```

### JS

```js
// Set stagger delays on grid children — call once on page load
function setStaggerDelays(gridSelector, interval) {
    var grids = document.querySelectorAll(gridSelector);
    for (var g = 0; g < grids.length; g++) {
        var children = grids[g].querySelectorAll('[data-stagger-child]');
        for (var c = 0; c < children.length; c++) {
            children[c].style.transitionDelay = (c * interval) + 'ms';
        }
    }
}

// Usage:
setStaggerDelays('.feature-grid', 100);        // cards: 100ms
setStaggerDelays('.logo-wall-row', 80);        // logos: 80ms
setStaggerDelays('.steps-grid', 150);          // large blocks: 150ms
setStaggerDelays('.integration-grid', 100);    // cards: 100ms
```

### HTML

Add `data-stagger-child` to each grid child element. Use `data-stagger-child="small"` for logos and small items.

### Cleanup

After the stagger completes, clear the inline `transitionDelay` so it does not interfere with other transitions:

```js
// Inside the IntersectionObserver callback, after adding 'visible':
var children = section.querySelectorAll('[data-stagger-child]');
if (children.length > 0) {
    var interval = 100; // match the stagger interval used
    var cleanupDelay = (children.length - 1) * interval + 800;
    setTimeout(function() {
        for (var j = 0; j < children.length; j++) {
            children[j].style.transitionDelay = '';
        }
    }, cleanupDelay);
}
```

## 4. Card Hover Lift

Cards lift upward and highlight their border on hover. Must only activate AFTER the entrance animation completes — otherwise the hover `transform` conflicts with the entrance `transform`.

**When to use**: Feature cards, integration cards, use-case cards, comparison table cards. NOT on buttons (buttons use `translateY(-1px)` from `visual-style.md`).

> ⚠️ **`data-hover-lift` is mandatory on every card that should hover-lift.** The stagger CSS rule `.reveal.visible [data-stagger-child]` has CSS specificity 0-3-0, which permanently overrides any card `:hover { transform }` rule (specificity 0-2-0 or lower). The only escape is the reveal-done handoff — which only fires when `[data-hover-lift]` elements exist in the section. Every hoverable card element in HTML **must** have the `data-hover-lift` attribute. Without it, hover lift silently does nothing.

### The Reveal-to-Hover Handoff

This is a CSS architecture pattern that prevents entrance and hover transitions from fighting:

1. During entrance: the card is inside `.reveal` — entrance `transform` is active
2. After entrance completes: JS swaps `.reveal` for `.reveal-done` — hover `transform` takes over
3. Without this swap, hovering during entrance causes the card to jump (two transforms compete)

### CSS

```css
@media (prefers-reduced-motion: no-preference) {
    /* After entrance, enable hover transitions */
    .reveal-done [data-stagger-child] {
        transition: transform 0.2s ease-in-out, border-color 0.3s linear;
    }
}

/* Hover cue: the border change works for everyone; the lift only moves when motion is allowed */
[data-hover-lift]:hover {
    border-color: var(--surface-2);
}
@media (prefers-reduced-motion: no-preference) {
    [data-hover-lift]:hover {
        transform: translateY(-4px);
    }
}
```

### JS

```js
// Inside IntersectionObserver callback, after section becomes visible:
var liftCards = section.querySelectorAll('[data-hover-lift]');
if (liftCards.length > 0) {
    var interval = 100;
    var handoffDelay = (liftCards.length - 1) * interval + 800;
    setTimeout(function() {
        section.classList.remove('reveal');
        section.classList.add('reveal-done');
        for (var j = 0; j < liftCards.length; j++) {
            liftCards[j].style.transitionDelay = '';
        }
    }, handoffDelay);
}
```

### Arrow Slide (companion pattern)

Text links inside hoverable cards can slide their arrow on card hover:

```css
.text-link::after {
    display: inline-block;
    transition: transform 0.2s ease-in-out;
}
[data-hover-lift]:hover .text-link::after {
    transform: translateX(4px);
}
```

## 5. Counter Animation

Numbers count up from 0 to target value with ease-out easing, triggered when the section scrolls into view.

**When to use**: Hero KPI numbers, Stats sections, platform metrics. Only for numeric values — never animate text.

### JS

```js
function animateCounter(el) {
    var target = parseFloat(el.getAttribute('data-count-to'));
    var prefix = el.getAttribute('data-count-prefix') || '';
    var suffix = el.getAttribute('data-count-suffix') || '';
    var decimals = parseInt(el.getAttribute('data-count-decimals')) || 0;
    var duration = 2000;
    var start = performance.now();

    function update(now) {
        var elapsed = now - start;
        var progress = Math.min(elapsed / duration, 1);
        var eased = 1 - Math.pow(1 - progress, 3); // ease-out cubic
        var current = target * eased;
        el.textContent = prefix + current.toFixed(decimals) + suffix;
        if (progress < 1) requestAnimationFrame(update);
    }
    requestAnimationFrame(update);
}
```

### Integration with Scroll Reveal

Counters trigger after their section enters the viewport, with a short delay so the section fade-in starts first:

```js
// Inside IntersectionObserver callback:
var counters = section.querySelectorAll('[data-count-to]');
if (counters.length > 0) {
    setTimeout(function() {
        for (var i = 0; i < counters.length; i++) animateCounter(counters[i]);
    }, 400); // 400ms after section appears
}
```

### HTML

```html
<!-- Initial text content = final displayed value.
     This is the reduced-motion fallback AND the no-JS fallback.
     Do NOT use "0", "0%", "$0M" as initial values — reduced-motion users
     would see incorrect data (zero customers, zero uptime) permanently. -->
<span data-count-to="99.99" data-count-suffix="%" data-count-decimals="2">99.99%</span>
<span data-count-to="2.4" data-count-prefix="$" data-count-suffix="M" data-count-decimals="1">$2.4M</span>
<span data-count-to="500" data-count-suffix="+">500+</span>
```

The element's initial text content **must equal the final displayed value** — it is the reduced-motion fallback and the no-JS fallback. Using "0" as the initial value means users who have reduced-motion enabled, or whose browser blocks JS, see permanently incorrect data.

### Hero Counter Trigger (load-based, not scroll-based)

Counter animations in the **Hero** section cannot use the scroll observer (Hero is above the fold and must not have `.reveal`). Use a load-based trigger instead:

```js
// Hero counter trigger — runs on DOMContentLoaded, not on scroll
document.addEventListener('DOMContentLoaded', function() {
    if (window.matchMedia('(prefers-reduced-motion: reduce)').matches) return;
    var heroCounters = document.querySelectorAll('.hero [data-count-to]');
    if (heroCounters.length === 0) return;
    // Small delay so the hero content settles before counting
    setTimeout(function() {
        for (var i = 0; i < heroCounters.length; i++) {
            animateCounter(heroCounters[i]);
        }
    }, 300);
});
```

This is separate from the scroll-observer combined script. Include it **in addition to** the combined script when the Hero has counter elements.

## 6. Marquee / Ticker

Continuously scrolling horizontal strip for logo walls or testimonial strips. Pure CSS — no JS required.

**When to use**: Social proof logo walls (alternative to static grid), testimonial strips. Optional — static layouts are equally valid.

### CSS

```css
.marquee {
    overflow: hidden;
    position: relative;
}

.marquee-track {
    display: flex;
    gap: 58px;
    width: max-content;
    animation: marquee-scroll 30s linear infinite;
}

.marquee:hover .marquee-track {
    animation-play-state: paused;
}

@keyframes marquee-scroll {
    from { transform: translateX(0); }
    to { transform: translateX(-50%); }
}

@media (prefers-reduced-motion: reduce) {
    .marquee-track {
        animation: none;
    }
}
```

### HTML

Duplicate the content so the loop appears seamless:

```html
<div class="marquee">
    <div class="marquee-track">
        <!-- Original items -->
        <div class="marquee-item">Logo 1</div>
        <div class="marquee-item">Logo 2</div>
        <div class="marquee-item">Logo 3</div>
        <!-- Duplicate for seamless loop -->
        <div class="marquee-item">Logo 1</div>
        <div class="marquee-item">Logo 2</div>
        <div class="marquee-item">Logo 3</div>
    </div>
</div>
```

The duplicate set must be an exact copy. The `translateX(-50%)` moves by exactly half the track width (the original set), creating a seamless loop.

## 7. Text Reveal

Hero heading words appear one by one with staggered opacity + slide-up.

**When to use**: Hero headings ONLY. Never on subtitles, body text, or labels — readability trumps drama. Optional — a simple section reveal on the hero is equally valid.

### CSS

```css
@media (prefers-reduced-motion: no-preference) {
    .text-reveal-word {
        display: inline-block;
        opacity: 0;
        transform: translateY(12px);
        animation: text-reveal-in 0.6s cubic-bezier(0.16, 1, 0.3, 1) forwards;
    }

    @keyframes text-reveal-in {
        to {
            opacity: 1;
            transform: translateY(0);
        }
    }
}
```

### JS

```js
function splitTextReveal(selector) {
    if (window.matchMedia('(prefers-reduced-motion: reduce)').matches) return;
    var el = document.querySelector(selector);
    if (!el) return;
    var words = el.textContent.trim().split(/\s+/);
    el.innerHTML = '';
    words.forEach(function(word, i) {
        var span = document.createElement('span');
        span.className = 'text-reveal-word';
        span.style.animationDelay = (i * 60) + 'ms';
        span.textContent = word;
        el.appendChild(span);
        // Add space between words
        if (i < words.length - 1) el.appendChild(document.createTextNode(' '));
    });
}

// Usage — call after DOM ready:
splitTextReveal('.hero h1');
```

**Constraint**: Total reveal time must stay under 1s. At 60ms per word + 600ms base duration, the real limit is 7 words (6×60 + 600 = 960ms). A 12-word heading takes 11×60 + 600 = 1,260ms — over the ceiling. If the heading exceeds 7 words, skip text reveal and use a standard fade-in on the whole heading instead (no split, no stagger).

## 8. Advanced: Canvas Gradient Background

> ⚠️ **Conflict with design system**: `shared/visual-style.md` §1 explicitly rejects "abstract gradients". Use this pattern only when the user explicitly requests it and understands it deviates from the default aesthetic.
> The default when no product visual is available is a plain `var(--bg)` background — no canvas, no gradient.

Animated mesh gradient rendered on a `<canvas>` behind the hero. Uses achromatic colors only (surface-1 values), so it technically avoids chromatic color — but the gradient itself is still abstract decoration.

**When to use**: Only if the user explicitly requests animated background motion and accepts the deviation from "content as decoration". Achromatic gradient only (gray-to-transparent, not color-to-color).

**When NOT to use**: Default page generation. When a product visual, screenshot, or code block is available. When the page already has motion (stagger, counter). When the user has not requested it.

**Required**: Must include the `prefers-reduced-motion` guard — the rAF loop must not run when motion is reduced.

### JS

```js
function initGradientCanvas(canvasSelector) {
    // Reduced-motion guard — rAF loop must not run when motion is reduced
    if (window.matchMedia('(prefers-reduced-motion: reduce)').matches) return;
    var canvas = document.querySelector(canvasSelector);
    if (!canvas) return;
    var ctx = canvas.getContext('2d');
    var w, h;

    function resize() {
        w = canvas.width = canvas.parentElement.offsetWidth;
        h = canvas.height = canvas.parentElement.offsetHeight;
    }
    resize();
    window.addEventListener('resize', resize);

    var points = [
        { x: 0.2, y: 0.3, vx: 0.0003, vy: 0.0002 },
        { x: 0.8, y: 0.2, vx: -0.0002, vy: 0.0003 },
        { x: 0.5, y: 0.8, vx: 0.0002, vy: -0.0002 }
    ];

    function draw() {
        ctx.clearRect(0, 0, w, h);
        points.forEach(function(p) {
            p.x += p.vx; p.y += p.vy;
            if (p.x < 0 || p.x > 1) p.vx *= -1;
            if (p.y < 0 || p.y > 1) p.vy *= -1;

            var grad = ctx.createRadialGradient(
                p.x * w, p.y * h, 0,
                p.x * w, p.y * h, w * 0.4
            );
            grad.addColorStop(0, 'rgba(245, 245, 245, 0.8)');
            grad.addColorStop(1, 'rgba(245, 245, 245, 0)');
            ctx.fillStyle = grad;
            ctx.fillRect(0, 0, w, h);
        });
        requestAnimationFrame(draw);
    }
    draw();
}

// Usage:
initGradientCanvas('.hero-canvas');
```

```css
    overflow: hidden;
}

    position: absolute;
    inset: 0;
    width: 100%;
```

## 9. Advanced: Magnetic Card Tilt

Cards tilt slightly toward the cursor on hover, adding depth perception.

**When to use**: Feature showcase cards, pricing tier cards. Optional — standard hover lift is the default.

**When NOT to use**: On mobile (no cursor). On small cards where the tilt looks exaggerated.

### JS

```js
function initMagneticTilt(selector) {
    // Reduced-motion guard
    if (window.matchMedia('(prefers-reduced-motion: reduce)').matches) return;
    var cards = document.querySelectorAll(selector);
    cards.forEach(function(card) {
        card.addEventListener('mousemove', function(e) {

            card.style.transform = '';
        });
    });
}
```

## 10. Accordion

Progressive disclosure component for FAQ sections and feature detail panels. Smooth open/close via `max-height` transition with full keyboard accessibility.

**When to use**: FAQ sections, pricing feature breakdowns, any content benefiting from show/hide. One item open at a time (accordion pattern) is the standard.

### CSS

### JS

```js
function initAccordion(containerSelector) {
    var container = document.querySelector(containerSelector);
    if (!container) return;
    var items = container.querySelectorAll('.accordion-item');

    items.forEach(function(item, index) {
        var trigger = item.querySelector('.accordion-trigger');
        var body = item.querySelector('.accordion-body');
        if (!trigger || !body) return;

        // ARIA setup — an item marked data-open starts expanded
        var bodyId = 'acc-body-' + index;
        var startOpen = item.hasAttribute('data-open');
        body.id = bodyId;
        trigger.setAttribute('aria-expanded', startOpen ? 'true' : 'false');
        trigger.setAttribute('aria-controls', bodyId);
        if (startOpen) body.classList.add('open');

        trigger.addEventListener('click', function() {
            var isOpen = trigger.getAttribute('aria-expanded') === 'true';
            // Close all (one-open accordion pattern)
            items.forEach(function(other) {
                var t = other.querySelector('.accordion-trigger');
                var b = other.querySelector('.accordion-body');
                if (t) t.setAttribute('aria-expanded', 'false');
                if (b) b.classList.remove('open');
            });
            // Open this one if it was closed
            if (!isOpen) {
                trigger.setAttribute('aria-expanded', 'true');
                body.classList.add('open');
            }
        });

        // Arrow key navigation between triggers
        trigger.addEventListener('keydown', function(e) {
            if (e.key !== 'ArrowDown' && e.key !== 'ArrowUp') return;
            e.preventDefault();
            var dir = e.key === 'ArrowDown' ? 1 : -1;
            var next = items[(index + dir + items.length) % items.length];
            var nextTrigger = next.querySelector('.accordion-trigger');
            if (nextTrigger) nextTrigger.focus();
        });
    });
}

// Usage:
// initAccordion('.faq-list');
// To open the first item by default: <div class="accordion-item" data-open>
// initAccordion('.pricing-features-list');
```

### HTML

```html
<div class="faq-list">
    <div class="accordion-item">
        <button class="accordion-trigger" type="button">
            <span>Question text here?</span>
            <span class="accordion-icon" aria-hidden="true">+</span>
        </button>
        <div class="accordion-body">
            <p>Answer text here.</p>
        </div>
    </div>
</div>
```

**Rules**:
- Always use `<button type="button">` — never `<div>` or `<span>`. Real buttons get keyboard access and ARIA semantics for free.
- `max-height` must exceed the tallest possible answer. `400px` for standard FAQ; `600px` for long-form content.
- Do NOT animate `height` directly — requires reading `offsetHeight` each time and is fragile. `max-height` is the safe pattern.
- Do NOT use `display: none` toggle — the `max-height` transition requires the element to remain in the layout.

## 11. Mobile Nav Toggle

Hamburger button that opens/closes navigation on narrow screens. Includes Escape key and outside-click handling.

**When to use**: All Page Skills — mobile nav toggle is a standard requirement, not optional. Activates below 768px (`max-width: 767px`, the same breakpoint as `shared/navigation.md`).

**Backdrop-filter trap**: every fixed nav has `backdrop-filter: blur(12px)` (Design Rules), and an element with `backdrop-filter` becomes the containing block for its `position: fixed` descendants. A `.nav-links` panel inside the blurred element is then positioned against the nav, not the viewport. Put the blur on a pseudo-element (`nav::before { content: ""; position: absolute; inset: 0; z-index: -1; backdrop-filter: blur(12px); }`) or render the menu panel outside the blurred element.

### CSS

```js
function initMobileNav() {
    var toggle = document.querySelector('.nav-toggle');
    var navLinks = document.querySelector('.nav-links');
    if (!toggle || !navLinks) return;

    toggle.addEventListener('click', function() {
        var isOpen = toggle.getAttribute('aria-expanded') === 'true';
        toggle.setAttribute('aria-expanded', String(!isOpen));
        navLinks.classList.toggle('nav-open', !isOpen);
    });

    // Close on outside click
    document.addEventListener('click', function(e) {
        if (!e.target.closest('nav') && navLinks.classList.contains('nav-open')) {
            toggle.setAttribute('aria-expanded', 'false');
            navLinks.classList.remove('nav-open');
        }
    });

    // Close on Escape and return focus to toggle
    document.addEventListener('keydown', function(e) {
        if (e.key === 'Escape' && navLinks.classList.contains('nav-open')) {
            toggle.setAttribute('aria-expanded', 'false');
            navLinks.classList.remove('nav-open');
            toggle.focus();
        }
    });
}
// Call on page load: initMobileNav();
```

### HTML


**Rules**:
- `top: var(--nav-h)` is mandatory — mobile menu must open below the fixed nav, not at `top: 0`. Take `--nav-h` from the active style's nav spec.
- `position: fixed` + `z-index: 999` — the menu must overlap page content.
- Return focus to the toggle on Escape close — accessibility requirement.
- `aria-label="Open menu"` — screen readers cannot see the visual hamburger bars.
- **Separate menu panel** (the backdrop-filter fix above): give it its own class (`.nav-panel`), never `.nav-links` — the desktop `.nav-links { display: flex }` rule overrides the `hidden` attribute and shows a second link row under the nav on desktop. Add `[hidden] { display: none !important; }` once per page as a guard. Hide the panel **outside** the media query too — `.nav-panel { display: none; }` at every width, then `.nav-panel.nav-open { display: flex; }` inside `@media (max-width: 767px)`. A panel styled only inside the media query shows as a bare link row on desktop.

```js
function initCarousel(selector) {
    var carousel = document.querySelector(selector);
    if (!carousel) return;
    var track = carousel.querySelector('.carousel-track');
    var items = carousel.querySelectorAll('.carousel-item');
    var dots = carousel.querySelectorAll('.carousel-dot');
    var prevBtn = carousel.querySelector('.carousel-prev');
    var nextBtn = carousel.querySelector('.carousel-next');
    if (!track || items.length === 0) return;

    var current = 0;

    function goTo(index) {
        current = (index + items.length) % items.length;
        track.style.transform = 'translateX(-' + (current * 100) + '%)';
        dots.forEach(function(dot, i) {
            dot.classList.toggle('active', i === current);
            dot.setAttribute('aria-current', String(i === current));
        });
    }

    if (prevBtn) prevBtn.addEventListener('click', function() { goTo(current - 1); });
    if (nextBtn) nextBtn.addEventListener('click', function() { goTo(current + 1); });
    dots.forEach(function(dot, i) {
        dot.addEventListener('click', function() { goTo(i); });
    });

    // Touch / swipe — checks horizontal vs. vertical to avoid misfiring on page scroll
    var touchStartX = 0;
    var touchStartY = 0;
    track.addEventListener('touchstart', function(e) {
        touchStartX = e.touches[0].clientX;
        touchStartY = e.touches[0].clientY;
    }, { passive: true });
    track.addEventListener('touchend', function(e) {
        var dx = touchStartX - e.changedTouches[0].clientX;
        var dy = touchStartY - e.changedTouches[0].clientY;
        // Only swipe if horizontal movement dominates and exceeds 50px threshold
        if (Math.abs(dx) > Math.abs(dy) && Math.abs(dx) > 50) {
            goTo(current + (dx > 0 ? 1 : -1));
        }
    }, { passive: true });

    // Keyboard — fires when the carousel wrapper has focus
    carousel.setAttribute('tabindex', '0');
    carousel.addEventListener('keydown', function(e) {
        if (e.key === 'ArrowRight') goTo(current + 1);
        if (e.key === 'ArrowLeft') goTo(current - 1);
    });

    goTo(0); // initialize state
}

// Usage:
// initCarousel('.feature-carousel');
// initCarousel('.testimonial-carousel');
```

- `role="region" aria-label="..."` — makes the carousel a landmark navigable by screen readers.

## 14. Combined Script Template

For convenience, the full animation script combining scroll reveal + stagger + hover handoff + counter animation. Agents copy and adapt this template:

```js
(function() {
    if (window.matchMedia('(prefers-reduced-motion: reduce)').matches) return;

    // --- Counter animation ---
    function animateCounter(el) {
        var target = parseFloat(el.getAttribute('data-count-to'));
        var prefix = el.getAttribute('data-count-prefix') || '';
        var suffix = el.getAttribute('data-count-suffix') || '';
        var decimals = parseInt(el.getAttribute('data-count-decimals')) || 0;
        var duration = 2000;
        var start = performance.now();
        function update(now) {
            var elapsed = now - start;
            var progress = Math.min(elapsed / duration, 1);
            var eased = 1 - Math.pow(1 - progress, 3);
            el.textContent = prefix + (target * eased).toFixed(decimals) + suffix;
            if (progress < 1) requestAnimationFrame(update);
        }
        requestAnimationFrame(update);
    }

    // Largest stagger delay actually set on these nodes (works for 80 / 100 / 150ms intervals)
    function maxStaggerDelay(nodes) {
        var max = 0;
        for (var i = 0; i < nodes.length; i++) {
            var d = parseFloat(nodes[i].style.transitionDelay) || 0;
            if (d > max) max = d;
        }
        return max;
    }

    // --- Scroll-triggered reveal ---
    var observer = new IntersectionObserver(function(entries) {
        entries.forEach(function(entry) {
            if (!entry.isIntersecting) return;
            var section = entry.target;
            section.classList.add('visible');
            observer.unobserve(section);

            // Trigger counters
            var counters = section.querySelectorAll('[data-count-to]');
            if (counters.length > 0) {
                setTimeout(function() {
                    for (var i = 0; i < counters.length; i++) animateCounter(counters[i]);
                }, 400);
            }

            // Reveal-to-hover handoff
            var liftCards = section.querySelectorAll('[data-hover-lift]');
            if (liftCards.length > 0) {
                var maxDelay = maxStaggerDelay(liftCards) + 800;
                setTimeout(function() {
                    section.classList.remove('reveal');
                    section.classList.add('reveal-done');
                    for (var j = 0; j < liftCards.length; j++) {
                        liftCards[j].style.transitionDelay = '';
                    }
                }, maxDelay);
            }

            // Clean up stagger delays for non-lift children
            var staggered = section.querySelectorAll('[data-stagger-child]');
            if (staggered.length > 0 && liftCards.length === 0) {
                var cleanupDelay = maxStaggerDelay(staggered) + 800;
                setTimeout(function() {
                    for (var k = 0; k < staggered.length; k++) {
                        staggered[k].style.transitionDelay = '';
                    }
                }, cleanupDelay);
            }
        });
    }, { threshold: 0.1 });

    // Observe all reveal sections
    var sections = document.querySelectorAll('section.reveal');
    for (var s = 0; s < sections.length; s++) observer.observe(sections[s]);

    // --- Set stagger delays ---
    function setStaggerDelays(gridSelector, interval) {
        var grids = document.querySelectorAll(gridSelector);
        for (var g = 0; g < grids.length; g++) {
            var children = grids[g].querySelectorAll('[data-stagger-child]');
            for (var c = 0; c < children.length; c++) {
                children[c].style.transitionDelay = (c * interval) + 'ms';
            }
        }
    }

    // Adapt these selectors to match the page's grid containers:
    // setStaggerDelays('.feature-grid', 100);
    // setStaggerDelays('.logo-wall-row', 80);
    // setStaggerDelays('.steps-grid', 150);

    // --- Hero counter trigger (load-based, not scroll-based) ---
    // Hero is above the fold and must NOT have .reveal — IntersectionObserver never fires for it.
    // Include this block when the Hero section has [data-count-to] elements.
    document.addEventListener('DOMContentLoaded', function() {
        var heroCounters = document.querySelectorAll('.hero [data-count-to]');
        if (heroCounters.length === 0) return;
        setTimeout(function() {
            for (var h = 0; h < heroCounters.length; h++) animateCounter(heroCounters[h]);
        }, 300);
    });
})();
```

## 15. Anti-Patterns

| Rule | Why |
|------|-----|
| No bounce or spring easing | Looks playful/toy-like, conflicts with the minimal professional aesthetic |
| No animation on body text paragraphs | Readability — text must be instantly readable when scrolled to |
| No entrance animation on nav or footer | These are chrome, not content — animating them feels broken |
| No autoplay video or audio | Accessibility and user respect |
| Total section entrance ≤ 1s | Content delayed beyond 1s feels sluggish, not elegant |
| No parallax on text content | Makes text unreadable during scroll |
| No more than 1 canvas background per page | Multiple canvas elements compete for attention and GPU |
| No stagger on single-item sections | Stagger with 1 child is just a delayed entrance — use plain reveal |
| Card hover only after entrance completes | The `.reveal-done` gate prevents transform conflicts |
| No `animation-fill-mode: forwards` on entrance | Use class-toggle (`.visible`) instead — forwards locks the element and prevents hover states. Sole exception: §7 Text Reveal's per-word spans, which are never interactive |
| No autoplay on carousel | WCAG 2.2.2 — users reading content cannot stop the movement fast enough |
| `<div>` or `<span>` as accordion trigger | Keyboard users cannot reach it; screen readers cannot identify it as interactive — always use `<button type="button">` |
