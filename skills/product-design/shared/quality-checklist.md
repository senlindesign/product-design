# Page Quality Checklist

> Applicable to all pages generated by Product Design Skills.
> Concrete values in this checklist are Minimal defaults (`shared/visual-style.md`). With Business, Colorful, or Editorial active, check against the active style file instead: sections 2–7 (color, shadow, type, spacing, radius), the narrow-screen table in §8, the hover timings and focus color in §9 (style file §6 and §8), and §13's palette examples — a palette the active style file defines on purpose (e.g. Colorful's warm canvas) is not an AI default. All structural, content, accessibility, and motion-safety checks apply in every style.

---

## 1. Structure Check

- [ ] Page has a clear information hierarchy: first screen communicates product value, subsequent sections progressively deepen
- [ ] Each section has an independent informational purpose, not duplicating the same information as other sections
- [ ] Section order follows the user's cognitive flow (awareness → interest → trust → action)
- [ ] No "empty sections" — every section has substantive content to support it

## 2. Color Silence

- [ ] All neutral colors are pure achromatic (zero hue shift) — no slate/zinc/cool gray
- [ ] Chromatic color occupies <10% of visible page area; CTA uses `var(--accent)` (default = black/white)
- [ ] No different background colors for different sections
- [ ] No colored decorations on icons/cards (colored circular backgrounds, gradient bars, colored borders)
- [ ] No gradient CTAs, glow effects, or semi-transparent colored overlays
- [ ] If brand color present: used only via `--accent` variable? Only on allowed-list elements? `--accent-text` contrast sufficient?

## 3. Shadowless Depth

- [ ] Zero box-shadow site-wide
- [ ] Hierarchy established via background color steps (#FFF → #F5F5F5 → #E9E9E9 or #0A0A0A → #141414 → #1F1F1F)
- [ ] No artificial lighting effects (inner shadow, drop shadow, text shadow)

## 4. Typography as Architecture

- [ ] Three font family switching for hierarchy (display sans / mono label / body sans)
- [ ] Weight 500 covers 70%+ of all text — no bold/regular switching for emphasis
- [ ] Hero heading ≥ 3× body text (e.g., body 18px → heading ≥ 54px)
- [ ] Heading negative tracking ≈ -2% of font size
- [ ] Subtitles weakened via opacity 0.5, not a different shade of gray
- [ ] Labels (LABEL): 12px / mono / 400 / uppercase / +0.72px tracking / opacity 0.3-0.4
- [ ] If custom font: Google Fonts link updated? Tracking adjusted for font type? Weight 500 available (or fallback plan)?

## 5. Content as Decoration

- [ ] Hero visual comes from product screenshots/code/work, not illustrations, abstract gradients, or stock photos
- [ ] No purely decorative graphic elements (geometric patterns unrelated to the product, wavy lines, background particles)

## 6. Spacing Rhythm

- [ ] Section spacing ≥ 180px *(N/A for single-block pages: 404, Downloads — those use 128px hero top + 58px hero bottom)*
- [ ] Hero top whitespace ≥ 128px *(N/A for 404 pages — those use viewport-fill centering)*
- [ ] Heading-to-content distance ≈ 58px
- [ ] Logo wall and footer padding ≥ 128px
- [ ] Page does not look like a compact list — generous breathing space throughout

## 7. Radius Grading

- [ ] Buttons 2px, feature cards 8px, content cards 16px — not all the same value
- [ ] No 999px fully-rounded buttons

## 8. Responsive

- [ ] Layout displays correctly at desktop width (≥1024px), no content overflow
- [ ] Content is readable at narrow width (≤767px), no overlap or truncation
- [ ] Multi-column layouts stack sensibly on narrow screens
- [ ] Narrow-screen spacing follows `visual-style.md` §3 reference table (180→96 / 128→80 / 58→40 / 32→24 / left-right 32→20) — not linearly scaled or independently invented values
- [ ] No horizontal scrollbar: full-width sections use `width: 100%` not `100vw` (100vw includes scrollbar width)

## 9. Basic Interaction States

- [ ] Button hover: `transform 0.2s ease-in-out` (translateY(-1px) or opacity change)
- [ ] Link hover: `opacity 0.3s linear`
- [ ] Clickable elements have cursor: pointer
- [ ] Focus state visible: `:focus-visible { outline: 2px solid var(--text); outline-offset: 2px }` (zero-shadow system uses outline, not box-shadow); inside dark sections, override to `--text-inverse`
- [ ] Nav buttons (CTA/login) always at `opacity: 1`, not overridden by `.nav-links a` dimming styles

## 9b. CSS Completeness (mandatory for composed pages)

These four items are the classic source of "each section looks right in isolation, but breaks when assembled":

- [ ] **No undefined variables**: every `var(--x)` has a declaration in `:root` or theme block. Search all `var(--` and verify each one — referencing a non-existent variable (e.g., `--text-rgb`) silently invalidates the entire rule, causing elements to disappear without error
- [ ] **Light components on dark surfaces have explicit color overrides**: `.btn-outline`, borders, icons, etc. on dark sections / dark Hero / transparent nav cannot use `var(--text)` as-is — it matches the background and becomes invisible (same class of error as the nav specificity trap)
- [ ] **Fixed nav compensates document flow**: when nav uses `position: fixed`, `body` must have `padding-top: var(--nav-h)`, otherwise Hero's 128px top whitespace measures from the viewport top and the heading sits under the nav
- [ ] **Nav content edges align with section content edges**: 32px horizontal padding goes on the inner `.container`, not directly on `<nav>`

## 10. Content Authenticity

- [ ] No fabricated customer testimonials or user quotes
- [ ] No fabricated statistics or performance metrics
- [ ] Example data is marked as examples, not disguised as real data

## 11. Semantics and Readability

- [ ] Reasonable HTML semantics (only one h1, section/nav/footer etc.)
- [ ] Body text font size ≥ 16px, line-height 1.6-1.7
- [ ] Text contrast meets basic readability standards

## 12. Scope Control

- [ ] Does not include business logic outside V1 scope (form submission, routing, payment, database)
- [ ] Page can be opened and rendered correctly in a browser
- [ ] Delivery notes declare which features are visual presentation and which are not implemented

## 13. Anti-Convergence Check

- [ ] Color scheme is not an AI-default combination (cream+terracotta, dark+neon, purple gradients)
- [ ] Feature showcase is not all three-column equal-width cards (consider bento grid, alternating rows, etc.)
- [ ] Design choices can be traced back to specific product/brand characteristics
- [ ] Pages generated from different briefs have observable differences in structure and visuals

## 14. Animation & Motion

- [ ] All CSS animations inside `@media (prefers-reduced-motion: no-preference) { ... }`
- [ ] All JS animation code guarded by `prefers-reduced-motion` check — exits early if reduce
- [ ] Scroll reveal uses consistent timing: 0.8s entrance, 100ms card stagger, 80ms logo stagger (from `shared/interaction-patterns.md`)
- [ ] Card hover lift (-4px) only activates after entrance animation completes (`.reveal-done` handoff)
- [ ] No animation on nav or footer sections
- [ ] No per-paragraph or per-line text animation — revealing a whole section container (which includes its paragraphs) is fine
- [ ] Total entrance delay for any section (reveal + max stagger) ≤ 1s
- [ ] Counter animations: scroll-into-view trigger for below-fold sections; DOMContentLoaded trigger for Hero (Hero is above the fold — IntersectionObserver never fires for it)
